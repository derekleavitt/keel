# A server action authorizes once; a stream is a decision that has to keep being made

T-20 predicted the server-action model would "have nothing to say about" a stateful
connection. The gap turned out to be sharper than that, and it is entirely about time.

Every authorization in this codebase resolves at the moment of a request: `requireScope()`,
`visibleVia`, `roleOnList`. The answer is produced, used, and discarded — a server action
that took a second longer would still be correct, because it re-asks on the next call.

A stream has no next call. Authorizing at connection time and then holding the socket open
means the decision silently becomes "whatever was true when they connected". Revoke someone's
share, and their tab keeps receiving change notifications until they close it. Not the
contents — the design makes sure of that — but the *timing*, which is enough to know who is
working on what and when.

So the stream re-authorizes on a timer, and closes itself with a `revoked` event when the
answer changes. The client stops rather than reconnecting, because reconnecting would be
answered with 403 forever and the page it is updating is about to become unreadable anyway.

**Anything long-lived needs its authorization re-taken, not remembered.** Streams, websockets,
polling loops holding a token, background jobs acting on a user's behalf, a signed URL with a
long expiry. The question is not "may they" but "may they *still*", and only the second one
has an answer that expires.

## The other half: never send the data

The stream carries `{"channel":"list:abc"}` and nothing else. The client refetches through
the ordinary authorized query.

That is not a bandwidth decision. Pushing rows down the connection would require
re-implementing every visibility rule at the socket layer, and getting it wrong there fails
open — a subscriber sees data no page would have shown them. Sending only "something moved"
makes the worst case a refetch that returns nothing.

for a machine. Same shape: an authorization decision correct in one temporal context and
wrong in another.
