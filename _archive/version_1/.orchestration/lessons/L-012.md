# Committed derived state is stale by construction

`RESUME.md` and `status.md` are generated from repository state, and both were committed.
A cold clone therefore opened `RESUME.md` and was told to deal with uncommitted changes
that existed only on the machine where it was last generated — because the file is written
*before* the commit that would make it accurate, so it permanently describes a dirty tree.

This is the failure the architecture warns about for the graph artifact, reappearing in
the handoff documents that exist specifically to survive a cold start.

Both are now gitignored, and `pnpm loop:status` is step one of every session rather than
an optional refresh. The general rule: **if a file can be regenerated from the repository,
regenerating it is the only way it can be trusted.**

Found by cloning the repository fresh and reading it as a new session would — a check
worth repeating whenever the handoff path changes.
