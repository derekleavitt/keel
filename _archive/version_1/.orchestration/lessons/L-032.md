# Describe the shape, do not import the vendor, to validate at a boundary

The v1 route handlers needed to parse request bodies against contract schemas. The obvious
`parseBody(request, schema: ZodType<T>)` does not compile in `apps/web`, because Zod is not
a dependency there — and `.claude/rules/web.md` says not to add one to reach a feature.

The tempting fixes are both wrong. Adding `zod` to the app erodes the boundary the rule
exists to hold. Typing the parameter `unknown` and casting throws away the checking that
was the entire point.

The third option costs six lines: describe the *shape* of a schema without naming what
produces one.

```ts
export interface Parser<T> {
  safeParse(input: unknown):
    | { success: true; data: T }
    | { success: false; error: { issues: readonly { path: PropertyKey[]; message: string }[] } };
}
```

Every contract schema satisfies this structurally, with no adapter and no wrapper. The app
gets full inference on `parsed.data`, and imports nothing from Zod.

**A structural type is how a boundary stays a boundary without also becoming a wall.** The
owning package publishes the shape it guarantees; consumers depend on the shape rather than
the implementation; swapping the library changes one file. The same move works for anything
a boundary needs to describe but must not depend on — a logger, a clock, a storage driver.

The signal that this is needed is specific and easy to recognise: *a type-only import that
the dependency rules forbid.* Reach for the shape before reaching for the dependency.
