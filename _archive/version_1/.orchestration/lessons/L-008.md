# No owning package for revalidatePath, so cache invalidation has no correct home

@keel/auth/session solves headers() for feature packages. Nothing solves
revalidatePath. Two agents worked around it differently, a third shipped without it.

Every framework API a feature package needs must have exactly one owning package that
re-exports it, or agents will each invent an answer.

**Resolved by T-02.** `@keel/runtime` owns the sanctioned crossings and records why each
one is allowed. `revalidatePath` is allowed because cache invalidation is inseparable from
the mutation that caused it; `headers()`, `redirect()` and route types are deliberately
not, with the reason written down beside them.

Promoted from `rule` to `lint`: `biome.json` restricts `next/*` imports inside
`testbed/**`, `packages/contracts`, `packages/db`, `packages/ui` and `examples/**`, with an
error message naming the replacement. A rule an agent must read is weaker than one it
cannot violate — three agents read the rule in run 2 and worked around it three different
ways.
