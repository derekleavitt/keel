# $defaultFn() is a JavaScript default and never reaches SQL

Adding `priority` with `.$defaultFn(() => 'none')` generated:

```sql
ALTER TABLE "todo" ADD COLUMN "priority" "todo_priority" NOT NULL;
```

No `DEFAULT`. That succeeds on an empty table and fails on any table that already has
rows — which is every real database. `.default('none')` produces
`DEFAULT 'none' NOT NULL` and works.

**The dangerous part is why nothing caught it.** Every check was green: typecheck, unit
tests, the PGlite suite, even the schema tests that read `information_schema`. A test
database is created empty and migrated immediately, so a migration that only breaks on
populated tables is structurally invisible to it. The failure appeared the moment the
migration met the local development database — one that happened to have rows.

Enforcement is a static check over committed migration SQL, because it catches the whole
class rather than this instance: no `ADD COLUMN ... NOT NULL` without a `DEFAULT`, and no
migration that both drops and adds (usually a rename that silently loses data).

**General rule:** an empty-database test suite cannot verify migrations. Anything whose
correctness depends on existing rows needs a different kind of check. Related: [[L-016]],
where the same suite's cost model was also wrong.
