# T-03 — todos: quick add and mark done

9 PGlite tests, 4 browser tests. Quick add is one field and one keypress; the input clears
and keeps focus so a second todo needs no mouse.

## The predicted friction did not appear

T-03 was expected to expose that "the territory model has no rule for referential
dependencies between tables forced to share a schema directory". It did not — because the
schema split put every table in `packages/db/src/schema/`, so `todo.list_id` references
`list.id` directly with no cross-package problem at all.

The constraint that made the earlier decision necessary is the same one that dissolved
this one. Worth recording as a case where an earlier fix removed a predicted problem
rather than deferring it.

## Real friction: optimistic updates

The obvious toggle — `checked={row.done}` plus an `onChange` calling a server action —
**does not move when clicked**. React re-renders from props that have not changed yet, so
the tick reverts until the round trip lands.

Playwright said it precisely: *"Clicking the checkbox did not change its state."* Nine unit
tests passed throughout; the query layer was correct the entire time. Only a browser could
see it. [[L-015]]

Fixed with `useOptimistic`, plus client-side sorting that mirrors the query's `order by
done, position` — an optimistic update that changes state but not order still looks broken.

## Ownership check the foreign key does not give you

`createTodo` verifies the target list belongs to the caller before inserting. The foreign
key only proves the list *exists*; without the explicit check a user could file a todo into
someone else's list by guessing an id. There is a test for it.
