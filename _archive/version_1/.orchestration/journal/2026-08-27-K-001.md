# K-001 — local development database

First friction of the first feature, found before a line of feature code: T-01 needs auth,
auth needs a database, and nothing in the repo provided one.

Five real bugs surfaced, every one of them only by running the thing:

1. No local database story at all. `pnpm db:up` now brings one up in Docker.
2. My own `db-up` script checked `docker --version` and called it a day — the CLI installs
   independently of the daemon, so the real failure was an unreadable socket error.
3. Postgres 18 changed the volume mount convention. The old path crash-loops the container.
4. **Nothing loaded `.env`.** `pnpm db:migrate` — a documented getting-started step — could
   never have worked. See [[L-011]].
5. **The auth schema was missing `account.issuer`, so every sign-up returned 500.** Green
   through typecheck, lint, unit tests, build and PGlite tests. See [[L-010]].

Number 5 is the one that matters. The schema was hand-written from memory of what Better
Auth requires, and nothing in the gate could catch it because nothing ever performed a
sign-up. Six agents worked in this repo without noticing.

Enforcement added: `apps/web/e2e/auth.spec.ts` performs a real sign-up against a real
database. It would have failed on the first run.

**What this says about the loop:** it works. Four of these five bugs were invisible to
every check in the gate and to six independent agents. Building the app is what found
them.
