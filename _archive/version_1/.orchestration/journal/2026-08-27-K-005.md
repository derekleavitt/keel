# K-005 — mutation queue, and a diagnosis I got wrong twice

Shipped `useSerialMutations` in `@keel/ui`, 25 browser tests green. But the interesting
part is that **K-005's premise was wrong**, and finding that out took two failed fixes.

## The sequence

T-06 saw a checkbox tick apparently vanish when preceded by other mutations. I diagnosed a
race between concurrent optimistic mutations, wrote it up as L-021, and filed K-005 to
build a queue.

1. **Built the queue.** Still failed.
2. **Found a real bug in my own hook** — the queued callback ran outside `startTransition`,
   where React 19 will not apply a `useOptimistic` update. Fixed it. Still failed.
3. **Stopped guessing and queried the database.**

```
 title | done | priority
-------+------+----------
 Alpha | t    | high
 Beta  | f    | medium
```

Every write had landed. Five POSTs, five 200s, correct rows. **Nothing was ever lost.**

The defect was on the read side: every action called `revalidatePath('/lists')` while the
user is on `/lists/[id]`. Revalidating a parent does not invalidate a nested dynamic
segment, so the server was right and the client served a cached payload — externally
indistinguishable from a write that never happened.

One argument fixes it: `revalidatePath('/lists', 'layout')`.

## What I should have done first

Check the source of truth before theorising about the mechanism. The symptom pointed at
concurrency, both concurrency theories were wrong, and a single `psql` query would have
redirected the whole investigation at step one instead of step three.

The loop-guard's identical-failure breaker was at 1 of 3 when I stopped guessing. It would
have caught me eventually — but "eventually" is two wasted fixes later, and the breaker
does not know the difference between a hard problem and a wrong theory.

## L-021 rewritten, not amended

The lesson now leads with the correction. A lesson recording a wrong diagnosis is worse
than none: the next agent inherits the wrong model with the authority of something already
written down.

## The queue shipped anyway

Kept on its own merits rather than the one it was built for — it keeps `useOptimistic`
updates inside a transition where React 19 requires them, and collapses a burst of clicks
into one refresh rather than one per click. A good change justified by a bad diagnosis.
