# T-07 — the agenda, and the question it was scheduled to force

8 unit tests spanning three features, 5 browser tests, 30 browser tests total green.

## The decision

The agenda reads todos, the lists they belong to, and their tags. It belongs to none of
them. That was recorded as unresolved at decomposition and deliberately left open, because
a guessed answer would have been indistinguishable from a considered one until something
real depended on it.

**Resolved: a cross-feature read model lives in a package that depends on several features
and is depended on by nothing but the app.** It is a leaf in the dependency graph, and it
writes no SQL of its own — it calls each feature's own read functions and merges them, so
every table keeps exactly one package that knows how to query it.

Written up as `docs/adr/0001-cross-feature-read-models.md` with the rejected alternatives,
because the reasons matter more than the conclusion.

## The first draft was already wrong

T-04 shipped `listAgenda` inside `testbed/todos`, joining `list` for a name. It worked, all
tests passed, and nobody would have flagged it in review.

That is exactly how ownership decays: the next cross-feature field makes todos read a third
table, and "the todos package" quietly becomes "the package that knows about everything" —
one reasonable commit at a time. Narrowed to `listDueTodos`, returning `listId` and not the
list's name.

**The feature did not reveal a missing capability. It revealed that a decision I had
already made, without noticing I was making it, was the wrong one.**

## Two things fell out

`KeelDatabase` moved to `@keel/db`. A composition package needs the database type without
writing SQL, and five identical `XDatabase` aliases were five reasons for packages to
depend on drizzle directly — including one that writes no queries at all.

`territories.yaml` now exists *in this repository*. It had only ever lived in the scratch
repo, so the open question it recorded was invisible to anyone reading Keel. A question
recorded where nobody will read it is not recorded.

## Timezone

`today` resolves on the client, because only the browser knows the user's zone. A
server-computed day shows the wrong thing to everyone not on the server's clock, and the
PRD's bar is "correct at midnight without a refresh" — precisely when that mismatch
surfaces.
