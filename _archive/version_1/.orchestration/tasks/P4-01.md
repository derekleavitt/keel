# Territory schema with shared-service and serialized tiers

CORRECTED FROM FIELD RESULTS. Three tiers, not two — see architecture §7 and §12.
The original owns/read_only model produced worse architecture in 3 of 3 trials.

- owned: one territory writes it, guarded at write time
- shared service: any territory may extend additively (auth, ui)
- serialized: everyone touches it, needs an ordering rule (schema.ts, contracts barrel)

## Acceptance

- [ ] Zod schema for territories.yaml covering all three tiers
- [ ] Regression: a requireUser()-shaped helper is placeable in a shared-service package
- [ ] Serialized files carry an explicit ordering rule, not a permission bit
- [ ] Validated against the run-1 territory map, which must be flagged as insufficient
