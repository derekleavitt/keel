# Attach files to a todo

Avatars, attachments, imports, exports — every platform needs file handling.

Proves the **storage** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [x] Upload, download and delete, all authorization-checked
- [x] Storage is behind a boundary; swapping S3 for local disk touches one package
- [x] Size and content-type limits enforced server-side, not just in the browser
- [x] Orphaned files are cleaned up when their todo is deleted

## Watch for

First binary data and first genuinely external service. Expect the vendor-boundary
rule to be tested for real.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.
