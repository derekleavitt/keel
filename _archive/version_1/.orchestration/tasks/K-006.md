# A feature package needs a cookie that is not the session

## Friction

Multi-tenancy needs an *active organization* per request, and the natural home for that is
a cookie. `@keel/runtime` deliberately does not re-export `cookies()`, with the reasoning
written down beside it: *"a feature package wanting raw headers almost always wants the
session"*.

That reasoning was right and is now incomplete. The active organization is genuinely not
the session — it is a per-request preference the user changes by clicking a switcher, and
`@keel/auth/session` has no business knowing about tenancy, which is a testbed concept.

Without a sanctioned path, the alternatives are all bad: add `next` to a feature package
(lint error, and correctly so), thread the raw value from the app through every call, or
put tenancy into `@keel/auth` where it does not belong.

## Acceptance

- [x] `@keel/runtime` exposes a narrow, documented cookie accessor
- [x] The reason it is allowed through the boundary is recorded, as with `revalidatePath`
- [x] `packages/runtime/src/index.ts` states when NOT to use it — session data still comes
      from `@keel/auth/session`
- [x] A feature package can read and write a preference cookie without depending on `next`
