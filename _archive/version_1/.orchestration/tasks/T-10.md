# Share a list with another user

Ownership stops working the moment two people touch one thing. This is the first real authorization problem.

Proves the **permissions** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [x] A list can be shared with another user at viewer or editor level
- [x] Every query respects the grant, not just the UI
- [x] A test proves a viewer cannot mutate and a non-grantee sees nothing
- [x] Revoking access takes effect immediately
- [x] Authorization is expressed once, not re-derived in each query helper

## Watch for

`userId`-first scoping is the only authorization pattern Keel demonstrates, and it
cannot express "someone else may read this". Expect the branded-`UserId` discipline to
strain, and expect a need for something `examples/notes` does not show.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.
