# Every timestamp column stores an instant in a type that has no time zone

Every `timestamp()` column in the schema — `created_at`, `updated_at`,
`session.expires_at`, `job.run_at` — is `timestamp` **without** time zone, while the values
written are UTC instants from JavaScript `Date`.

That is fine while nothing compares them in SQL. The moment something does, Postgres has to
reconcile a zone-less column with a zone-aware expression:

```sql
where run_at <= now()   -- run_at is timestamp, now() is timestamptz
```

Postgres converts `now()` to the server's local wall clock, so a job stored as UTC is not
"due" unless the server runs in UTC. It fails silently and completely — the queue simply
never claims anything, and every test that asserts a job ran reports zero.

T-12 works around it by passing a JS `Date` as a parameter, which also makes "now"
controllable in tests. The workaround is good; the schema is still wrong.
