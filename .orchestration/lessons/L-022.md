# db:sync and db:migrate cannot share a database

`pnpm db:sync` runs `drizzle-kit push`, which writes the schema straight to the database
and **records nothing in the migration ledger**. `pnpm db:migrate` then tries to apply
those same migrations to tables that already exist, and fails.

The failure is unusually hard to read. drizzle-kit reports the underlying Postgres error as
the literal string `undefined`, so the visible output is a stack trace with no cause. The
migration SQL is valid — applying it by hand works — which sends the investigation toward
the SQL and away from the ledger. What actually settled it was comparing the journal
against `drizzle.__drizzle_migrations`: seven entries, five applied, and the two missing
ones describing tables that were already there.

I introduced `db:sync` in K-004 to let a feature branch run the app, and did not say that
it desynchronises the ledger. Using it once made every later `db:migrate` on that database
fail.

**The rule:** pick one per database. `db:sync` is for a throwaway local database on a
branch; a database that has ever been pushed to must be reset with `pnpm db:reset` before
`db:migrate` will work again.

Related: this is the second time swallowing migrate output with `2>&1 || true` hid a real
failure from me — the first was in T-04. The gate skips e2e by default, so a broken
development database is invisible until a browser test hangs waiting for a page that is
throwing.
