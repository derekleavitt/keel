# PGlite is real Postgres, but it is not the real driver

The job queue from T-12 shipped green: 13 unit tests, a dead-letter path, backoff, an
admin page. The first time anything drained it over HTTP against the actual development
database — during T-16, four tasks later — the claim query threw. Twice, for two unrelated
reasons, in the same ten lines.

```
TypeError: The "string" argument must be of type string … Received an instance of Date
TypeError: Cannot read properties of undefined (reading '0')
```

Both come from the same blind spot. `createTestDatabase()` runs PGlite, which speaks the
`node-postgres` protocol; production runs `postgres`. Drizzle's *query builder* hides the
difference. A raw `` sql`…` `` template does not — it hands values straight to the driver
and returns whatever the driver returns.

- `postgres` refuses a `Date` as a parameter; PGlite accepts it. Fixed by passing
  `asOf.toISOString()` with an explicit `::timestamptz`.
- `postgres` returns rows as an array; PGlite returns `{ rows }`. Reading `.rows`
  unconditionally worked in every test and was `undefined` in production.

The unit suite could not have caught either, and passing was not evidence of anything: the
queue's central query had **never once executed against the driver it ships with**.

**A raw SQL template is a driver boundary, and every driver boundary needs one test that
crosses it for real.** PGlite is excellent for what it is — genuine Postgres semantics,
real constraints, real cascades, fast enough to run per-test — and it is not a substitute
for exercising the wire format. The rule that falls out:

> Anything using `database.execute()` with a raw template must have at least one test that
> reaches it through the running application, not only through PGlite.

The webhook e2e now does exactly that, by draining the queue over HTTP the way a scheduler
would. That test is the enforcement — and note how long the gap stayed invisible. The
capability was marked done, the gate was green, and the feature had never run.

Related: [[L-010]], where hand-written auth schema passed every check because nothing ever
performed a sign-up. Same shape: complete coverage of everything except the one path that
matters.
