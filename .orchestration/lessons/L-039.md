# Browser tests against `next dev` measure the compiler and hide the product

The browser suite ran against `next dev` from Phase 0 until T-19. Switching it to
`next build && next start` — one line of config — turned up four things at once, none of
them related to the feature being built, and every one of them a real defect that had been
invisible for months.

**1. A rate limiter nobody had ever met.** Better Auth enables rate limiting in production
and disables it in development. The first production-build run failed a quarter of its tests
with `429 Too many requests`, and the limiter was working perfectly. Nothing had ever
reached it. The numbers are now written down in `packages/auth` rather than inherited,
because a limit nobody chose is a limit nobody can defend when a customer behind a corporate
NAT hits it.

**2. A navigation that cancelled itself.** `router.push('/dashboard')` followed immediately
by `router.refresh()` aborts the navigation it follows — push starts fetching the RSC
payload, refresh re-requests the current route, the browser drops the first. Against `dev`
the payload is usually already in hand and it worked. On a real network it is "signing in
sometimes does nothing".

**3. Two guards that keyed off `NODE_ENV`.** `next start` sets `NODE_ENV=production`, so
"refuse this in production" also refused it on the developer's own machine, and the webhook
receiver on `http://127.0.0.1` became unreachable. The fix was to ask the question actually
meant — *is this instance deployed?* — using `BETTER_AUTH_URL`, which must already be right
for authentication to work at all. See [[L-034]]: a guard that blocks testing is a guard
someone deletes.

**4. The suite's own timings were meaningless.** Compilation happened inside whichever
assertion first touched a route, so failures landed on whichever test was unlucky. Four
concurrent sign-ups took 27 seconds cold and 40 milliseconds on the built server.

**Test the artefact that ships.** `pnpm verify` builds immediately before the browser step,
so Turbo serves the build from cache and the change costs about a second. What it buys is
that every production-only behaviour — rate limiting, real RSC fetches over the network,
production `NODE_ENV`, minified client code — is exercised by the gate rather than
discovered by a user.

Related: [[L-033]], where the job queue's central query had never run against the driver it
ships with. Same shape, one layer up — coverage of everything except the thing that runs.
