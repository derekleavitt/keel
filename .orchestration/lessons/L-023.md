# A preference cookie outlives the session that set it

The active workspace is stored in a cookie. Cookies are per-browser, not per-session, so
signing out left it behind — and the next person to sign in on that machine inherited the
previous user's workspace selection.

`resolveScope` refuses an organization the new user is not a member of, so the dangerous
version of this is blocked by construction. The version that still bites is when they *are*
a member: they land in a workspace they never chose, with nothing on screen explaining why
their own lists are missing.

It surfaced as a test failure that looked nothing like the cause — a "Switch to Team C"
button that was absent because Team C was *already active*, inherited from the sign-out
before it. The database was correct throughout; only the browser carried the stale state.

**Any preference cookie that scopes what a user can see must be cleared on sign-out.** The
membership check makes it safe; it does not make it correct.

Fixed by clearing the cookie before `signOut()`. Enforced by the sharing e2e tests, where
each user must now explicitly switch workspace after signing in — which is exactly what a
real user experiences.
