# requireUser() throws, but a page needs a redirect

`@keel/auth/session` offered only `requireUser()`, which throws. That is right for a
server action — an unauthenticated mutation is a bug or an attack, and should be loud.

But a person opening a protected page while signed out is doing something entirely
ordinary, and throwing turns it into a 500. The first protected page in the testbed hit
this immediately, and the tempting fix is for each page to resolve the session itself —
which is exactly the duplication [[L-004]] and the session-helper failure exist to prevent.

`requireUserOrRedirect()` now lives beside it in the owning package. Two variants, because
there are genuinely two situations.

Enforced by an e2e test asserting an anonymous visitor to `/dashboard` receives a redirect
with a sub-400 status rather than an error page.

**Also worth knowing:** `typedRoutes` checks route *literals*, so a helper cannot assemble
its destination from a parameter. Write the route out and vary only the query string.
