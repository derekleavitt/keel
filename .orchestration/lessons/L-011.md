# Next reads .env from the app directory, not the monorepo root

The README instructed users to create `.env` at the repository root. Every script and
`drizzle-kit` read it from there. **Next did not** — it only loads `.env` from the app
directory, so the app saw no environment at all.

The failure surfaced at request time as "DATABASE_URL: expected string, received
undefined", long after setup appeared to have succeeded: `pnpm db:up` worked,
`pnpm db:migrate` worked, the dev server started, the home page rendered. Only a route
that actually touched the database failed.

`apps/web/next.config.ts` now loads the root `.env` explicitly, so one file at the root is
the single source of truth. Values already present in the environment still win, so CI and
hosting platforms are unaffected.

The general rule: in a monorepo, **every tool that reads configuration must be pointed at
the same file explicitly.** Defaults differ per tool and the disagreement is silent.
