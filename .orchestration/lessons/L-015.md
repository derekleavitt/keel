# A checkbox driven from server state does not move when you click it

The obvious way to write a toggle — `checked={row.done}` with an `onChange` calling a
server action — is subtly broken. React re-renders the input from props, which have not
changed yet, so the tick reverts and only reappears once the round trip lands and the page
revalidates.

Locally that reads as a flicker. On a slow connection it reads as a broken checkbox, and
the user clicks it again.

Playwright caught it exactly: *"Clicking the checkbox did not change its state."* No unit
test would have — the query layer was correct throughout, and it is only wrong in the
browser.

React 19's `useOptimistic` is the fix: apply the change immediately, and it rolls back
automatically if the action fails. It must be updated inside a transition.

The client-side list is also sorted the same way the query sorts it (`done`, then
`position`), so an optimistic tick moves the row at once rather than waiting for the
server to reorder it. An optimistic update that changes state but not order is a
half-measure that still looks broken.

**General rule:** any control whose state comes from the server needs an optimistic path,
and the test that proves it must drive a browser. Related: [[L-010]] — typechecking proves
nothing about what a person experiences.
