# A module that mixes pure operations with request-bound ones cannot be used off the request path

`packages/auth/src/platform.ts` was written with everything about platform staff in it:
`isPlatformAdmin`, `grantPlatformAdmin`, `recordAdminAction`, and `requirePlatformAdmin()`.
It typechecked and the app worked.

Then `pnpm admin:grant` — the CLI that creates the first administrator, and the only way one
can be created — failed at import:

```
Cannot find package 'next/headers'
```

One function in the module resolved the current session, so importing *any* of it required a
web request. The CLI needed `grantPlatformAdmin`, which touches nothing but the database, and
could not have it.

The split is along a line worth naming: **does this function need to know who is asking?**

| Needs the request | Does not |
|---|---|
| `requirePlatformAdmin()` | `isPlatformAdmin(userId)`, `grant`, `revoke`, `list`, `record` |

The request-bound half moved to `session.ts` beside the other `require*` helpers; the rest
takes its inputs and a database handle and now works from a CLI, a job, a test and a request
alike.

**The signal is a dependency that only one function needs.** When a module imports something
heavy — a framework, a request context, a global — and only part of it uses that import, the
module is two modules. The cost is not felt until something tries to use the other half, and
the thing that tries is usually a script written at 11pm during an incident.

Related: [[L-032]], the same principle from the other direction — describe the shape you need
rather than importing the thing that provides it.
