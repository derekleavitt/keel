# Custom migrations need explicit statement breakpoints

`drizzle-kit generate --custom` is the sanctioned way to write a data migration — DDL
generation cannot know that existing rows need a tenant inventing for them. But the file it
creates is applied as a **single prepared statement** unless statements are separated by
`--> statement-breakpoint`.

Multi-statement SQL without those markers fails with `cannot insert multiple commands into
a prepared statement`, and the error names no file and no line. The migration is valid SQL
— running it by hand in psql works perfectly — which points the investigation at the
database rather than at the file format.

Every generated migration has these markers, so they read as decoration rather than
structure. They are structure.

A data migration also has to be **idempotent**: guarded inserts, `ON CONFLICT DO NOTHING`,
and `WHERE ... IS NULL` on backfills. A migration that cannot be safely retried will
eventually be run twice, on the day it half-fails.
