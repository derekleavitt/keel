# TypeScript 7 was chosen for a speed benefit that does not exist here

Phase 0 pinned TypeScript 7.0.2, and the reasoning recorded at the time was that the Go
rewrite is "much faster, which directly serves the Stop-hook gate". That was never
measured.

Measured now, on this repository:

| | cold typecheck of `apps/web` |
|---|---|
| TypeScript 7.0.2 | 636ms |
| TypeScript 5.9.3 | **573ms** |

TypeScript 5 is *faster* here. The Go rewrite's advantage does not materialise at this
scale, and the choice cost a real safety feature: **TS7 does not resolve Next's
`typedRoutes` ambient namespace**, so every route literal failed to typecheck — six errors
under TS7, zero under TS5 on identical code.

An agent hitting those six errors would reasonably conclude `typedRoutes` was broken and
disable it, losing route type safety to preserve a performance benefit that was never real.

Now pinned to 5.9.3. Revisit when TS7 handles ambient namespace merging, and **measure
before switching** — the gate's own timing output makes that trivial.

The general rule: a performance claim that has not been measured is not a reason. Related:
[[L-014]].
