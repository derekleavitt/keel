# The test database re-migrated for every test, and CI started timing out

`createTestDatabase()` applied every committed migration on every call. That is
O(tests x migrations), and it does not stay cheap — four migrations in, the `@keel/db`
suite took 11 seconds on a CI runner and blew vitest's 5s default, while passing locally in
well under one.

**A test that is green on the developer's machine and red in CI is the worst kind of
failure.** It teaches people the gate is unreliable, and an unreliable gate gets ignored or
disabled — which takes every other guarantee in this repository with it.

Raising the timeout would have hidden it. The fix is to stop doing the expensive thing:
PGlite can dump a migrated data directory and load it back, so migrations run **once per
process** and each test restores a snapshot instead. Same isolation, and the cost no longer
grows with the migration count.

Measured: the `@keel/db` suite went from 11.2s in CI to 1.36s.

A generous timeout remains in `vitest.shared.ts` as a safety net, documented as a net
rather than a fix — if a suite ever needs 30 seconds, something has regressed.

**General rule:** when CI is slower than local, the honest question is what the test is
doing that it should not have to do. Related: [[L-010]].
