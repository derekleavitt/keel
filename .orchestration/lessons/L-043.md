# A sentinel that collides with a legitimate value drops exactly the case it was meant to serve

The live-update endpoint takes a cursor: "I have seen up to change 41, tell me what happened
since." A client with no cursor should start from *now* rather than replaying history, so the
handler read:

```ts
if (cursor === 0) cursor = await currentCursor(organizationId);
```

`0` meant "not supplied". It is also the real cursor of **every tenant that has never changed
anything** — which is every tenant on its first page load. So the first change in a new
workspace was fast-forwarded past and never delivered: precisely the change a new user is
most likely to be watching for, and the one a demo shows first.

Nothing errored. The subscription connected, reported itself live, and stayed silent.

```ts
const raw = header ?? searchParams.get('cursor');   // null when absent
const supplied = raw === null || raw === '' ? null : Number(raw);
if (supplied === null) cursor = await currentCursor(organizationId);
```

**Absent and zero are different questions, and a numeric type cannot hold both.** The general
form: any time a sentinel is drawn from the same domain as real values — `0`, `-1`, `""`,
`Infinity` — the case it collides with is a real case, and it will be the one that breaks. Use
`null`/`undefined`, which are outside the domain by construction.

Worth noting how it was found: the browser test that caught it was the *polling fallback*
test, driving the endpoint directly with explicit cursors. The two streaming tests passed
throughout, because a live subscriber's first change arrives while its cursor is already
non-zero. **A degraded path tested as rigorously as the primary one is a second pair of eyes
on the same logic**, and here it was the pair that could see.
