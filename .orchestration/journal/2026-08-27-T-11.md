# T-11 — organizations, the threshold feature

The largest change in the backlog: **43 query helpers across 12 files**, every signature,
every predicate, the schema, the app layer and every test. 176 unit tests and 46 browser
tests green.

## The shape of the change

Every query took `userId: UserId`. Now every query takes `scope: Scope` — a branded pair of
user and tenant. That single substitution is what makes the acceptance criterion "no path
that forgets" mechanical rather than aspirational: **there is no signature that accepts a
user without a tenant**, so a partially-scoped query is not something this codebase can
express.

Tenancy is the outer boundary; ownership and sharing operate inside it. The predicates put
the tenant filter on the inner selects, so a grant that somehow pointed across tenants
still could not widen a result.

Todos carry no `organization_id`. They inherit tenancy from their list exactly as they
inherit access — one place decides which tenant a todo belongs to, rather than two that can
disagree.

## The data migration

`drizzle-kit generate` emits DDL and cannot know that existing rows need a tenant invented
for them. `generate --custom` is the sanctioned path, and two things about it are
non-obvious enough to have cost a cycle each:

- Statements need explicit `--> statement-breakpoint` markers, or the file is applied as
  one prepared statement and Postgres refuses. The error names no file and no line, and
  the SQL is valid when run by hand. [[L-024]]
- It must be idempotent. Guarded inserts and `WHERE ... IS NULL` backfills throughout,
  because a migration that cannot be retried will be run twice on the day it half-fails.

Verified against a database that already had users, lists and tags in it.

## Three real bugs, all mine

**A preference cookie outlived the session.** Signing out left the active workspace behind,
so the next person to sign in on that browser inherited it. `resolveScope` refuses a tenant
they are not a member of, so the dangerous version is blocked — but if they *are* a member
they land somewhere they never chose. It surfaced as a missing "Switch to Team C" button,
absent because Team C was already active. [[L-023]]

**Pages resolved a scope before checking auth**, turning an ordinary signed-out visit into
a 500. Same split as `requireUser` / `requireUserOrRedirect`, and for the same reason:
resolving a tenant for nobody is meaningless.

**A workspace dependency cycle**, created by putting the tenancy test in `testbed/orgs`
while lists and todos already depend on orgs for `requireScope`. Turbo refused the build.
The fix follows ADR 0001 — a cross-feature *test* belongs in the composition package, just
like a cross-feature query. The ADR turned out to describe more than it claimed.

## K-006: a cookie that is not the session

`@keel/runtime` deliberately withheld `cookies()`, reasoning that a feature package wanting
headers usually wants the session. Right, and incomplete: the active workspace genuinely is
not the session, and `@keel/auth` has no business knowing tenancy exists. Added as a narrow,
documented accessor with the reason recorded and an explicit note that nothing read from it
is trusted before a membership check.

## What the threshold actually revealed

This was the feature the growth backlog was built around — the one meant to prove whether
territories and impact analysis earn their place. The honest answer so far: **the
type system did the work.** Changing `userId: UserId` to `scope: Scope` produced 62
compile errors that were a complete, precise worklist, and following them to zero was
mechanical. No graph query would have told me anything `tsc` did not.

What the type system did *not* catch: the cookie outliving the session, the redirect
ordering, and the dependency cycle. Two of those needed a browser, and the third needed
Turbo. None needed a code graph.

That is evidence against P1-03 and P4-05 as designed, and it should be weighed before
either is built.
