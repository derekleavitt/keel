# T-04 — due dates and priorities

33 unit tests (9 calendar-date, 24 query) and 3 new browser tests. Dates are stored as SQL
`DATE` with `mode: 'string'`, asserted against `information_schema` rather than trusted.
Priority is a pgEnum declared least-to-most urgent, so `desc(priority)` sorts correctly
with no CASE expression.

## Two traps, both invisible to the existing checks

**An all-optional type accepts any object.** Adding a `filter` parameter before the
trailing `database` parameter broke every caller, and TypeScript said nothing: `TodoFilter`
has only optional fields, so the database handle satisfied it. Excess-property checking
applies to literals, not variables. The failure surfaced as
`DATABASE_URL: expected string, received undefined` — an error describing nothing about the
actual mistake. [[L-017]]

**`$defaultFn()` never reaches SQL.** `priority` was declared with `.$defaultFn(() =>
'none')`, which generated `ADD COLUMN "priority" ... NOT NULL` with no DEFAULT. That
applies cleanly to an empty table and fails on one with rows.

Everything was green while it was broken — typecheck, unit tests, the PGlite suite, even
the schema tests reading `information_schema`. **A test database is created empty and
migrated immediately, so a migration that only breaks on populated tables is structurally
invisible to it.** It failed the moment it met the local development database, which had
rows in it. [[L-018]]

Enforced with a static check over committed migration SQL, catching the class rather than
the instance: no `ADD COLUMN ... NOT NULL` without a `DEFAULT`, and no migration that both
drops and adds. Verified by injecting the original statement.
