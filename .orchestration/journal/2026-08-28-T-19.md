# T-19 — full-text search

Ranked search across todo titles, notes and list names, backed by Postgres full text.
91 new unit tests, 3 net new browser tests; 381 unit tests and 82 browser tests green, gate
back to 46s.

The feature took an afternoon. The rest of this entry is about what building it exposed,
which was worth considerably more.

## The ownership question had a good answer

**Watch for** predicted this would be "the first feature reading across every feature
package at once", sharpening the ownership question. It would have been, done the obvious
way — one query unioning todos and lists, holding both features' authorization rules in a
file that owns neither.

The shape that avoids it: **nobody searches across features.** Each feature exposes a
`SearchSource` that searches its own tables under its own visibility rule — `visibleVia`,
composed, not re-derived — and a composition package registers the sources and merges. That
file contains no SQL, no table names and no authorization logic, and adding a searchable
feature is a registration rather than an edit to a growing union.

Ranks are normalised **per source** before merging. `ts_rank` is a function of document
length, so a hit in a short `list.name` scores far above an equally relevant hit in a long
`todo.notes`; sorting the raw numbers together would put every list above every todo and
look deliberate. Normalising makes the per-source weight an explicit, arguable choice.

Two details worth keeping:

- **`websearch_to_tsquery`, never `to_tsquery`.** The latter expects an expression and
  raises on anything else, so every codebase reaching for it hand-writes a sanitiser — and
  that sanitiser is where the 500s live. The former parses what users already type, and
  cannot fail on any input. There is a test that throws `'; drop table todo; --` and an
  unmatched bracket at it.
- **The index is a generated column**, not a trigger and not a reindex job. That is the
  whole of "indexing keeps up with writes": there is no indexing step to fall behind, and a
  todo is searchable in the statement that created it.

## Then the browser suite went from 70 seconds to fifteen minutes

Switching the e2e `webServer` from `next dev` to `build && start` — one line, meant only to
stop measuring the compiler — surfaced four defects that had been invisible for months.

**A rate limiter nobody had ever met.** Better Auth enables it in production and disables it
in development. A quarter of the suite failed with `429`, and the limiter was working
correctly; nothing had ever reached it. The numbers are now written down rather than
inherited.

**A navigation that cancelled itself.** `router.push('/dashboard')` followed by
`router.refresh()` aborts the navigation it follows. Against `dev` the payload is usually
already in hand; on a real network it is "signing in sometimes does nothing".

**Two guards keyed off `NODE_ENV`.** `next start` sets production, so "refuse in production"
also refused on my own machine, and the local webhook receiver became unreachable. They now
ask the question actually meant — *is this instance deployed?* — via `BETTER_AUTH_URL`,
which has to be right for authentication to work anyway. [[L-039]].

## And the unit suite went to fifteen minutes for an unrelated reason

Turbo runs each package's tests concurrently; vitest inside each sizes its pool to the
machine. Neither knows about the other, so twenty-odd packages each claimed ten cores. Load
average past sixty; `testbed-todos` — 74 tests, 25 seconds alone — took over ten minutes.

`maxForks: 2` per package plus `turbo --concurrency=4` fixed it. [[L-041]].

## How badly I diagnosed all of this

Worth recording honestly, because the wasted effort was mostly self-inflicted.

The symptom was "everything is slow and some tests fail". I checked the database size, the
connection count, stale locks, the schema I had just changed, and the Postgres container —
all healthy — before running `uptime`, which answered it immediately.

Worse, I **started a dev server by hand and left it running**, so Playwright could not bind
its own and waited. Several of my measurements were taken against that, and one "8.7 minute
test run" was entirely my own squatting process. Then I repeatedly interrupted runs, leaving
orphaned workers holding cores, and took further measurements on a machine still busy with
the previous experiment.

A benchmark on a polluted machine is not a slow result, it is **no result**. The habit to
keep: kill the strays, wait for the load average to fall, measure one unit in isolation
first, and only then believe a number. A file that takes 12 seconds alone and 10 minutes in
its package is a scheduling fact, not a code fact, and the ratio says so immediately.

A fifth defect fell out of the same session: the webhook receiver in the browser tests
called `server.close()`, which waits for open connections — and one test deliberately holds
one open. The file hung for ten minutes with no error and no indication which test was
responsible. [[L-040]].

## Behaviour I changed deliberately, and one I did not

Three existing browser tests broke on the new engine. Each needed a decision rather than an
edit:

- **Empty query still lists todos.** A search box that blanks the screen when cleared reads
  as broken; that decision predates full text and survives it. Lists are excluded — `/lists`
  already exists for browsing containers.
- **Todo hits still show their list name.** The only genuinely cross-feature part of a
  result, so the composition layer attaches it, once, over the whole result set.
- **The `%` wildcard test was rewritten, not loosened.** Its assertion encoded `LIKE`
  escaping, which no longer exists; full text tokenises `50%` to `50`. The property worth
  keeping — punctuation does not become a match-everything pattern — is now asserted
  directly, alongside the exactness a user actually reaches for, a quoted phrase. [[L-026]].

One test I deleted rather than fixed: "editing a todo updates what it matches" tried to type
into a notes field that **does not exist in the UI**. Notes are settable only through the
API. The indexing property belongs in a unit test anyway, where it now lives with four
others; the missing editor is recorded as T-23.

## Against the graph prediction, seventh time

A feature spanning every package is the case a code graph is sold for. What this task
actually needed was `uptime`, `ps`, a per-file timing, and reading one Playwright config.
