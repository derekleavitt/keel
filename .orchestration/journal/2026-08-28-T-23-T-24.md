# T-23 and T-24 — notes editing, and seats

Two small tasks, both from gaps the previous ones exposed. 8 new unit tests in orgs (a package
that had none), 5 new browser tests; gate 69s.

## T-23 — a field that existed everywhere except the interface

`todo.notes` was in the schema, settable through the public API, indexed for full-text search
and rendered as the search snippet. There was no way to set it in the app. It surfaced when a
T-19 browser test tried to type into a control that did not exist.

**Notes commit on blur, not on change.** A date picker fires once when a date is chosen; a
textarea fires on every keystroke, and saving there is a request per character, a revalidation
per character, and a race between them. Blur is one save per edit and is the moment somebody
has actually finished. Debouncing is the same idea with a timer and one more way to lose the
last keystroke.

Two details the gap forced:

- **Focus-and-leave writes nothing.** Without the comparison, tabbing past a todo bumps
  `updated_at` and wakes every live subscriber to that list.
- **The draft adopts the server's value while unfocused.** Now that lists update live (T-20),
  a stale draft would otherwise be written back on the next blur, silently undoing somebody
  else's edit.

Passing `canEdit` through also fixed something older: the due-date and priority controls had
looked editable to viewers since T-10. The server always refused; the interface never said so.

## T-24 — the mechanism was ten lines, the number was the design

Seat enforcement copied the list-limit pattern exactly — checked in `addMember`, in the query
layer, so the public API meets the same refusal — and worked on the first run.

Then every sharing test failed. The free plan allowed **one** seat, so no free user could
share a list, invite anybody, or use an organization at all. The testbed's central feature had
become a paid feature, decided by a constant nobody had considered as a decision.

The tempting fix is to make the tests buy a plan first. That would have shipped the pricing
decision *and* coupled every multi-user test to billing, so a change to plans could break
sharing. Free now allows three: the limit is still demonstrable — a fourth member is refused,
with a test — and the feature it governs is usable without a subscription. [[L-046]].

Second decision, easier to get right and worse to get wrong: enforcement applies only when
**adding**. A tenant downgrading from ten seats to three still has ten people, and locking
seven out to enforce a number is worse than letting the count sit over. Changing an existing
member's role still works, and no billing event ever removes anybody.

## What T-24 revealed by accident

`packages/organizations` had **no unit tests**. Organizations shipped in T-11 — the task that introduced
`Scope`, the type every package now takes — and were covered only indirectly, through the
packages that consume a scope. Nothing had needed to assert on membership directly until a
seat limit did.

Eight tests now cover creation, invitation, roles and seats. Two of them are about
authorization and would have been worth having since T-11: a member cannot invite, and a
personal workspace cannot gain members whatever its plan says.

That is the second structural gap this backlog has surfaced in the orgs package, after
[[P7-01]] — it holds a platform primitive while living in `testbed/`, and it had no tests. Both
found by building something else on top of it.
