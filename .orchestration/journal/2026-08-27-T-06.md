# T-06 — filtering by tag, priority and done state

23 browser tests green. Filter state lives in the URL, so it survives a reload and can be
shared, and a GET form sidesteps `typedRoutes` refusing computed `Link` hrefs.

## Scoping proved for every combination, not the ones I thought of

`buildTodoListQuery` is exposed as a builder so its SQL can be rendered without a
connection. `scoping.test.ts` enumerates all **sixteen** subsets of the four filters and
asserts `"user_id" =` survives every one — plus that a user-supplied value containing
`' or 1=1 --` is parameterised rather than inlined.

A behavioural test proves scoping for the combinations someone thought to write. Rendering
the SQL proves it for the ones added next week.

Doing that needed a database handle that builds SQL and never connects, which Keel did not
have. `queryBuilder()` in `@keel/db/testing` is that, backed by drizzle's proxy driver
whose connection callback is never invoked.

## Tag filtering uses EXISTS, not a join

A todo carrying two of the selected tags must appear once. A join duplicates the row per
matching tag, and the bug only shows when someone selects two tags — which no obvious test
does.

## Two real findings

**Ambiguous accessible names.** `getByLabel('Priority')` matched three controls: the
filter and one per row. Playwright's strict mode caught what a screen-reader user would
have experienced as three identically-named controls with no way to tell them apart. The
filters now say "Filter by priority".

**Overlapping mutations can lose a write.** Setting a priority and immediately ticking a
checkbox silently drops the tick: it appears optimistically, the assertion passes, then the
row re-renders from server state fetched before the write landed.

I checked whether the redundant `router.refresh()` was the cause — each action already
calls `revalidatePath`. Removing it changed nothing; the race still reproduced. So the
cause is in how overlapping revalidations resolve.

Tests now wait for each write to settle, which is **a workaround and is labelled as one**.
The real fix is a mutation queue in shared UI, since every feature mutating from a list has
the same exposure — filed as K-005. A known limitation with a workaround is a different
thing from a passing test that quietly proves nothing. [[L-021]]
