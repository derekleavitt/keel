# T-09 — drag to reorder

21 unit tests in todos, 4 browser tests, 41 browser tests total green. Native HTML5 drag
and drop, no dependency added.

## The ordering module was reused, not reimplemented

`positionBetween`, `neighboursForMove`, `evenPositions` and `PositionExhaustedError` all
came from `@keel/testbed-lists` unchanged. Todos and lists now share one implementation of
fractional ordering, which matters because the subtle parts — computing the midpoint as
`before + (after - before) / 2` so it cannot overflow, and lifting the moved row out of the
sequence before finding its neighbours so a one-place move is not a no-op — are exactly the
parts a second implementation would get wrong.

## The renumber test proves the branch runs

Asserting the resulting order alone would pass even if the renumber branch were dead code:
the positions would be wrong but the sequence right. The test forces adjacent doubles
between two rows, performs a move, and then asserts the **minimum gap** afterwards is at
least a full step — spacing that pure halving from 1 could never produce.

## What the prediction got wrong

T-09 predicted transactions would be exercised for the first time. They already were —
`reorderList` has been transactional since T-02, with its own renumber test. The prediction
was written before that existed and nobody revisited it.

Third time a "Watch for" has been wrong, and the pattern is consistent: they were written
at decomposition, and the repo has moved since. They are still worth writing — a hypothesis
that fails is information — but they should be read as of their date, not as current.

## Two test-harness mistakes, both mine

Reading a row's `textContent` to get a title picked up every option label from its priority
select. And an assertion after a link click ran before navigation finished, reading the
previous page's rows as empty strings.

Neither was an application bug, and both produced failures that looked like application
bugs. Worth noting how often a red test in a browser suite is the test being wrong rather
than the app — a red suite still has to be diagnosed, not assumed.
