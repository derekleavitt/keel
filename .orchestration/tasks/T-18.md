# Admin surface with roles

Someone always needs to see across tenants.

Proves the **roles + admin** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [ ] Role model beyond membership: owner, admin, member
- [ ] An internal admin view that crosses organizations, access-controlled
- [ ] Every admin action is audited
- [ ] A test proves a member cannot reach admin routes

## Watch for

Second authorization model layered on the first. If T-10's approach was too narrow,
this is where it breaks.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.
