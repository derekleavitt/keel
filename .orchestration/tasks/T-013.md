# Give each run its own directory

`src/run.mjs` writes every trial to a fixed path — `runs/trial-0.txt`, `runs/trial-1.txt` — so
two runs started at the same time write to the same files. The second run's workers append into
the first run's trial file, the first run's oracle then reports numbers it never assigned, and
both runs look broken for reasons that have nothing to do with the strategy under test.

This was found the way the project intends things to be found: six agents were working in this
tree at once, and the agent implementing T-010 saw two runs fail that passed on rerun. It
attributed them to collisions on `runs/trial-0.txt` without confirming, which is the right level
of confidence to report — but the fixed path makes the mechanism obvious on inspection.

Worth naming what this is. The harness built to study lost updates on a shared file lost updates
on a shared file, because its own output path was shared state with no coordination. The fix is
the one the project's own results recommend: not a lock, but a layout where contention cannot
arise.

## Already fixed

T-007 changed trial paths to `runs/trial-<pid>-<i>.txt` while implementing failure injection —
unprompted, after its own first `npm test` run failed on exactly this collision. Two concurrent
invocations now get different pids and cannot collide. What remains is the part nobody asserted.

## Notes
- Depends on T-007 because that task also owns `src/run.mjs`. Do not start until it is merged.
- Strategy group files inherit the trial path (`hierarchical` writes `<file>.gN`), so fixing the
  trial path fixes those too — but assert it, because `compact()` globs for them and a stale group
  file from another run would be silently merged in.
- Resist adding a lock. The whole point of the result in the README is that a layout where
  collisions cannot happen beats a mechanism for resolving them.
