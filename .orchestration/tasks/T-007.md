# Add failure injection and non-uniform workers to the process harness

Two README Open items ("Non-uniform agents", "Failure injection") need harness support that does not exist. Every worker gets the same `--delay`, so the lockfile's `STALE_MS = 10_000` reclaim path and its "slow holder loses its lock" hazard have never been exercised. A hung worker makes `run.mjs` wait forever (no timeout), and a crashed worker makes the whole trial an error rather than a measurement. Also, `src/worker.mjs` does no argument validation: a missing `--file` becomes `undefined` and `--value` becomes `NaN` with an unhelpful stack. `run.mjs` records `elapsed: 0` for a trial that threw, which drags the median down.

## Acceptance
- [ ] `src/worker.mjs` accepts `--crash-at <ms>` (calls `process.exit(3)` after that many ms, racing the strategy) and `--hang` (never exits); missing `--file` or non-numeric `--value` exit 2 with a message on stderr
- [ ] `src/run.mjs` accepts `--slow <k> --slow-ms <ms>` (k workers get `--delay slow-ms`), `--faulty <k> --fault <crash|hang>` (k workers get the fault), and `--timeout <ms>` (hung workers are SIGKILLed and counted as faulty); faulty workers' values are excluded from the oracle's `expected` set
- [ ] `node src/run.mjs --agents 8 --strategy append --faulty 2 --fault hang --timeout 2000 --trials 2` exits 0 within 10s
- [ ] `node src/run.mjs --agents 8 --strategy naive --trials 3` exits 1 and `node src/run.mjs --agents 8 --strategy lockfile --trials 3` exits 0 (pins the README result table)
- [ ] A thrown trial records `elapsed` as the actual elapsed time, not 0; a test asserts the median for a run with one crashed worker is > 0
- [ ] `test/run.test.mjs` spawns the commands above and asserts exit codes; `node --test test/run.test.mjs` exits 0 in under 60s
- [ ] Output lines `strategy:` and `passed:` keep their current format (T-012 greps them)

## Notes
- Do not modify any strategy file; T-008 (lockfile) and T-009 (append) own those and T-008 depends on these flags.
- Default `--delay` is 25ms; `--crash-at 10` therefore crashes before the write in all three strategies. Document in the header comment that a crash *after* the write will surface as `unexpected: [v]`, which is the correct reading.
- Workers run from `runs/`, which is gitignored. Tests should use `--trials 1..3` to stay fast.
- `--hang` with `lockfile` currently blocks everyone for `STALE_MS` (10s); that is expected until T-008 makes it configurable.
