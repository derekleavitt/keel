# Sign up, sign in, sign out

The app is unusable without it, and every other feature needs a real session.

## Acceptance

- [ ] Sign-up, sign-in and sign-out routes exist and work against a real database
- [ ] Session survives a page reload
- [ ] An anonymous request to a protected route is redirected, not errored
- [ ] `requireUser()` from `@keel/auth/session` is used — no bespoke session resolution

## Already resolved

The database friction this feature exposed is fixed — see `.orchestration/tasks/K-001.md`
and `.orchestration/journal/2026-08-27-K-001.md`. `pnpm db:up && pnpm db:migrate` gives
you a working database, and sign-up already round-trips at the API level with an e2e test
covering it.

**What remains is the user-facing half:** sign-in and sign-up pages, a sign-out control, a
protected route that redirects anonymous visitors, and `requireUser()` actually used by
something.

## Watch for

Better Auth is configured but nothing has exercised it end to end. Expect friction
around protected-route patterns and where redirect logic belongs — `apps/testbed` or a
package.

This section is a hypothesis, not a specification. If the friction lands somewhere else,
that is the more interesting result — record it.
