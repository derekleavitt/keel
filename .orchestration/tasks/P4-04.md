# Worktree flow and integrator

The integrator merges branches in dependency order, running verify at each step.

The run-2 branches are the regression fixture — a known-hard case with real conflicts.

## Acceptance

- [ ] Merges the run-2 branches in dependency order
- [ ] Runs pnpm verify after each merge, halting on red
- [ ] Feature branches generate NO migrations at all; only the integrator runs db:generate,
      once, after merging. Committing a baseline turned a 2-way conflict into a guaranteed
      3-way one — see .orchestration/lessons/L-005.md
- [ ] Enforced, not just documented: a check rejects a branch containing new drizzle/ files
- [ ] Reports conflicts it could not resolve rather than guessing

## Pull condition

**PREDICTED, not scheduled.** This task is a hypothesis about what Keel will need. Do not
build it because it is next in the list.

Pull it when building a testbed feature actually demands it — when friction, a repeated
mistake, or a recorded lesson names this as the fix. Then it becomes `open`.

If the testbed never demands it, that is a finding: the prediction was wrong, and the
task should be deleted rather than built.
