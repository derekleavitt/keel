# No local development database

## Friction

T-01 (sign up / sign in) cannot be built or manually tested without a running Postgres.
The README says `cp .env.example .env` then `pnpm db:migrate`, but nothing in the
repository provides a database to point at, and no candidate is installed.

`pnpm verify` passing with no `.env` is a real property and it hides this: the gate is
green on a checkout where the application cannot actually run. Every new user and every
agent hits this wall on their first feature, and each will solve it differently — a
hosted Neon instance, a Homebrew Postgres, a hand-rolled container — which is the same
"three agents, three answers" failure the reference slice exists to prevent.

No `predicted` task covers this. The architecture assumed a database was somebody else's
problem.

## Acceptance

- [x] One command brings up a local Postgres from a clean checkout
- [x] One command tears it down
- [x] `.env` is created automatically if absent, with a generated auth secret
- [x] `pnpm db:migrate` succeeds against it
- [x] The app boots and a real sign-up round-trips
- [x] README's getting-started section is accurate end to end, with no missing step
- [x] `pnpm verify` still passes with no `.env` and no database running
