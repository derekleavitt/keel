# Price the cache, and let the cost model say that cost depends on concurrency

Three real `claude -p` calls (see T-024 and the fourth grooming), same prompt shape, same session,
minutes apart, at `claude-opus-5[1m]`:

| call | input | cache_creation | cache_read | output | cost_usd | duration_ms |
|---|---|---|---|---|---|---|
| 1 (cold) | 2 | 44,539 | 0 | 3 | 0.445475 | 3039 |
| 2 | 2 | 11,679 | 32,862 | 3 | 0.133306 | 3001 |
| 3 | 2 | 11,683 | 32,862 | 3 | 0.133346 | 2824 |

Against `src/pricing.mjs`'s opus rates, all three costs are reproduced to six decimals, and only,
at a 2x multiplier on cache writes and 0.1x on cache reads:

```
(44539 x 5 x 2                 + 2 x 5 + 3 x 25) / 1e6 = 0.445475
(11679 x 5 x 2 + 32862 x 5 x 0.1 + 2 x 5 + 3 x 25) / 1e6 = 0.133306
(11683 x 5 x 2 + 32862 x 5 x 0.1 + 2 x 5 + 3 x 25) / 1e6 = 0.133346
```

1x and 1.25x on the write do not match any of them. So both multipliers are verified by arithmetic
against vendor-reported costs; 2x is the recalled one-hour cache-write multiplier (the five-minute
write, 1.25x, is recalled and unverified). Incidentally this is the first external check of the
opus rates in `pricing.mjs`, and they held.

What the three calls say about the shape of an agent's overhead: the prefix is about 44,541 tokens
on every call, in three parts. A stable block of 32,862 tokens is written to cache once and read
on every later call. A volatile block of about 11,680 tokens differs between invocations and is
re-created at the write price every time; that one term is 88% of the warm price. And 2 tokens
of plain input. The warm cost, $0.133, is therefore the marginal cost of a dispatched Claude Code
agent, and it does not fall further with more calls: calls 2 and 3 agree to four decimals.

This changes the cost model structurally, not only numerically. The model has one price per input
token and one `OVERHEAD` per kind. In reality the overhead has three parts at three prices, and
which price the stable part is billed at depends on whether an identical prefix has been written
before the call starts, which is a function of concurrency. So the README's sentence "Calls,
tokens and cost do not change with concurrency; only time does" is false under caching. At N=100
partitioned on the measured constants: 1 cold and 99 warm (serial) is $13.64; 20 cold and 80 warm
(the harness default) is $19.57; 100 cold is $44.55. The README projects $1.50 at Haiku. Note the
asymmetry: the overhead the model assumed for `api` (200) is probably ~4x too high and the one for
`claude-code` (15,000) is 3x too low, so correcting both widens the gap between the kinds.

Three constants are now measured, from three calls on one machine. The project's rule since the
second grooming is that a constant changes only from a record, never by argument. These are
records. The rule's spirit is that the value is derived, so the constants are set from the fixture
by a test, not typed.

## Acceptance
- [ ] `src/pricing.mjs` exports `CACHE = Object.freeze({ write1h: 2, write5m: 1.25, read: 0.1 })`
      with a provenance comment stating that `write1h` and `read` are verified by arithmetic
      against all three documents in `test/fixtures/claude-p-47.json` and that `write5m` is
      recalled and unverified. `test/pricing.test.mjs` reproduces each of the three `total_cost_usd`
      values from its document's usage, the opus rates, `CACHE.write1h` and `CACHE.read`, to within
      1e-9, and asserts that write multipliers 1 and 1.25 reproduce none of them. If T-024 has not
      landed the fixture, the test reads the twelve usage numbers and three costs from constants in
      the test file with a comment saying they are transcribed from the owner's calls, and the
      report says the fixture is missing.
- [ ] `priceOf(usage, rates, cache = CACHE)` is exported from `pricing.mjs` and prices
      `{ inputTokens, outputTokens, cacheCreationInputTokens, cacheReadInputTokens }`.
      `agents.mjs`'s `costOf()` is not this task's to change (T-024 owns the file); `compare.mjs`
      uses `priceOf` now.
- [ ] `OVERHEAD` in `src/cost-model.mjs` becomes, per kind, `{ stable, volatile, uncached }`:
      `api: { stable: 0, volatile: 0, uncached: 200 }` (unchanged in total; the API transport sets
      no cache control) and `'claude-code': { stable: 32862, volatile: 11680, uncached: 2 }`.
      `ASSUMPTIONS.OVERHEAD` keeps the key names. A test derives the claude-code values from the
      fixture: `stable` is `cache_read_input_tokens` of call 2, `volatile` is the rounded mean of
      `cache_creation_input_tokens` of calls 2 and 3, `uncached` is `input_tokens`, and the three
      sum to within 2 of call 1's `cache_creation_input_tokens + input_tokens`. So the constant is
      derived, not authored. `LATENCY['claude-code']` becomes `3.0` with a comment saying it is the
      median wall-clock of three calls that each emitted 3 tokens, so it is an upper bound on fixed
      latency that includes a 44K-token prefill; a test asserts it equals the fixture's median
      `duration_ms` in seconds to one decimal.
- [ ] `project()` takes `cache: 'none' | 'session'` (default `'none'`) and `--cache` on the CLI.
      Under `'none'` every overhead token is priced at the input rate, as today except for the two
      changed constants. Under `'session'`: within each round, the first
      `min(concurrency, callsInRound)` calls are **cold** (`stable + volatile` at `CACHE.write1h`)
      and the rest are **warm** (`stable` at `CACHE.read`, `volatile` at `CACHE.write1h`);
      `uncached` and all variable input are at the input rate in both. The returned object gains
      `cache`, `coldCalls` and `warmCalls`. Tests assert at N=100 partitioned, opus, claude-code,
      `cache: 'session'`: concurrency `Infinity` gives 100 cold and a cost equal to
      `100 x 0.445475` within $0.01; 20 gives 20 cold / 80 warm; 1 gives 1 cold / 99 warm and a
      cost equal to `0.445475 + 99 x 0.133306` within $0.01; and that cost falls monotonically
      across the three. A test asserts `cache: 'none'` gives identical output to today's for every
      row of `--agents 100` **except** the claude-code rows, whose new values are taken from
      `project()`, not literals.
- [ ] The `--crossover` cost check (`every topology cost >= solo`) is run by a test under both
      cache modes at concurrency 1, 20 and unlimited for both kinds. If it is violated under
      `'session'` (later calls are cheap reads; `solo` pays one cold call but all the generation),
      that is a finding: the test asserts whatever is true and the report states it in one
      sentence, because it would be the first time distribution cost less than one agent here.
- [ ] The cost model's header comment and the `OVERHEAD` comment are rewritten to say the overhead

      how it splits, and that `api` remains a guess. No prose in `src/` may still say 15,000.
