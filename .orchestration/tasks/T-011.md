# Single source of truth for model pricing

`src/cost-model.mjs` (`MODELS`) and `src/agents.mjs` (`MODELS` + `PRICE`) each carry their own copy of model ids and per-million-token rates. The README's whole argument is projection-versus-measurement; if one table is edited and the other is not, the two scripts disagree about the price of the same tokens and the comparison is meaningless. Neither file records where the rates came from or when they were checked, which the README's "published per-token pricing" phrasing implies.

## Acceptance
- [ ] `src/pricing.mjs` exports `MODELS` (alias -> `{ id, input, output }`) plus `PRICING_SOURCE` (URL string) and `PRICING_CHECKED` (ISO date string)
- [ ] `grep -n "input: " src/cost-model.mjs src/agents.mjs` returns no per-million rate literals; both import from `./pricing.mjs`
- [ ] `node src/cost-model.mjs --agents 100` output is byte-identical to its output before this task (tests from T-003/T-004 still pass)
- [ ] `node src/agents.mjs --mock clean --agents 5 --topology partitioned` still exits 0
- [ ] `test/pricing.test.mjs` asserts every `MODELS` entry has finite positive `input` and `output`, a non-empty `id`, and that `PRICING_CHECKED` parses as a date; `node --test test/pricing.test.mjs` exits 0

## Notes
- Depends on T-004 and T-006 because they are the last tasks in the `cost-model.mjs` and `agents.mjs` ownership chains; this task must not run concurrently with them.
- Do not change any rate or model id in this task; the acceptance is byte-identical output. Verifying the rates against the vendor's current pricing page and updating `PRICING_CHECKED` is a deliberate separate step (do it, but if a rate changes, say so in the commit and expect T-012 to regenerate the README).
- `agents.mjs` keeps accepting raw model ids via `--model` (`MODELS[alias] ?? arg`); pricing for an unknown id falls back to zero as today.
