# Make concurrency a parameter of the cost model and export its assumptions

The cost model assumes every call in a round runs at once ("Concurrency is assumed unlimited"
in the README). The harness that would measure it, `src/agents.mjs`, defaults to
`--concurrency 20`, and the API has rate limits of the same order. The two disagree about the
one thing that decides the headline. By the model's own arithmetic, `partitioned` at N=100
with 20 calls in flight is 5 waves of 1.525s = 7.6s, against `solo` at 4.0s — it loses at zero
work and needs at least 50 calls in flight to win. The README's crossover table says
`partitioned: work >= 0`. Both are true; they are answers to different questions, and the first
real run would "disprove" the model for a reason that is the harness's configuration, not the
model's physics.

Fix the shape, not the constants: `project()` and `crossover()` take `concurrency` (default
`Infinity`, so every existing number is unchanged) and a round with k calls takes
`ceil(k / concurrency)` sequential waves. The CLI takes `--concurrency N`.

Separately, the constants every headline rests on — `OVERHEAD`, `TOKENS_PER_NUMBER`,
`OUTPUT_TOKENS_PER_SECOND`, `LATENCY` — are module-private. T-017 compares them against a
measured run and cannot import them. Export them under one name.

- [ ] `node src/cost-model.mjs --agents 100` output is byte-identical to its output before this task (`test/readme.test.mjs`'s cost-table and crossover tests still pass unchanged)

- [ ] `crossover({ agents: 100, concurrency: 20 })` reports `partitioned.at > 0` for both kinds, and `crossover({ agents: 100 })` still reports `partitioned.at === 0`; a test asserts both and that the reported point is exact (wins at `at`, does not win at `at - 1`), as the existing crossover test does
- [ ] `node src/cost-model.mjs --agents 100 --crossover --concurrency 20` exits 0 and prints a header line containing `concurrency 20`; with no `--concurrency` the crossover output is byte-identical to before

- [ ] `npm test` exits 0 and `npm run check` exits 0

## Notes
- Default `Infinity` is deliberate: the README is pinned cell-for-cell against the default output and T-019 (not this task) decides what to say about concurrency. Do not change any default output.
- `shared-lock` has one call per round, so `concurrency` never changes it; `solo` likewise. Only `partitioned`'s single round and `hierarchical`'s leaf and merger rounds split into waves. A test should assert `shared-lock` and `solo` seconds are identical at `concurrency` 1 and `Infinity`.
- `--concurrency` already appears in README.md (as an `agents.mjs` flag), so `test/readme.test.mjs`'s flag-documentation check will not fail on this task. Do not rely on that for any other new flag.
- Do not touch `src/agents.mjs` (T-015 owns it this wave) or `src/pricing.mjs`.
- Keep the printed table format (column headers, `─` rule, row regex `^(api|claude-code)\s+\S+\s+\d+\s+\d+\s+\d+\s+\$\d+\.\d+\s+\S+$`) stable; `test/readme.test.mjs` parses it.
