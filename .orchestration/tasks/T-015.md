# Record every call the agent harness makes, with timing

`src/agents.mjs` reports one `elapsed` for the whole run and totals for tokens. From that,
none of the cost model's time constants can be recovered: `LATENCY` (fixed per call) and
`OUTPUT_TOKENS_PER_SECOND` are the intercept and slope of a line through (output tokens, ms)
points, and the harness keeps no points. The first real run will produce one number per
topology and no way to say *which* assumption was wrong. The per-call tokens exist already
(`reply.inputTokens`, `reply.outputTokens`); the per-call time does not.

Keep a record for every call and, with `--record <path>`, write it as JSONL. One line per
call, one summary line at the end. This is the measurement side of the comparison the project
exists to make; T-017 reads it.

## Record format (T-017 depends on this exactly)

One JSON object per line, in call-completion order, with exactly these keys:

| key | type | meaning |
|---|---|---|
| `agent` | string | the label passed to `ask` (`"57"`, `"solo"`, `"merger L1.0"`, `"root L2.0"`) |
| `role` | string | `solo`, `leaf`, `merger`, `root`, or `shared` (shared-lock) |
| `level` | integer | hierarchical level; `0` for every other topology |
| `startedMs` | number | `now()` at call start minus `now()` at run start |
| `ms` | number | call duration, `now()` after the call minus `now()` before it (≥ 0) |
| `inputTokens` | integer | from the reply object; `0` when the transport returned a string |
| `outputTokens` | integer | same |
| `stopReason` | string or null | from the reply object; `null` for string replies and errors |
| `outcome` | string | `accepted`, `rejected`, or `errored` |
| `valuesIn` | integer | integers in the prompt the call was given |
| `valuesOut` | integer | integers in the reply (`0` for errored) |

The last line is `{"summary":true, "topology", "model", "agents", "fanout", "concurrency",
"calls", "inputTokens", "outputTokens", "costUsd", "elapsedMs", "ok"}` with `fanout` `null`
unless hierarchical and `model` the id or `mock:<mode>`, as `report()` already labels it.

## Acceptance
- [ ] `runAgents()` returns `outcome.calls`, an array of record objects as specified above, one per call that was attempted (errored calls included); its length equals `usage.calls + errored.length`
- [ ] Timing uses the injected `now`, so a test with a scripted `now` that advances by a fixed step asserts exact `ms` and `startedMs` values
- [ ] `--record <path>` writes the JSONL described above; `node src/agents.mjs --agents 12 --topology hierarchical --fanout 3 --mock clean --record <tmp>` exits 0 and the file has exactly 20 lines: 19 call lines (12 leaf + 4 + 2 + 1) and 1 summary line, every line parses as JSON, every call line has exactly the 11 keys above, and `role`/`level` counts match the `levels` block the CLI prints
- [ ] A test with a scripted transport returning `{ text, inputTokens, outputTokens, stopReason }` asserts `inputTokens`/`outputTokens`/`stopReason` land in the record, and that a throwing transport yields a record with `outcome: "errored"`, `inputTokens: 0`, `stopReason: null`
- [ ] `report()` output is unchanged except for one added line after `time`, of the form `latency  median <n>ms  p95 <n>ms  per call` (so the `levels` block `test/readme.test.mjs` pins verbatim is untouched)
- [ ] Without `--record` nothing new is written anywhere; a test asserts the output directory holds only the `--out` file after a run
- [ ] `node --test test/agents.test.mjs test/agents-topologies.test.mjs test/smoke.test.mjs` exits 0; `npm run check` exits 0
- [ ] `npm test` exits 0 **except** `test/readme.test.mjs`'s test "every flag and SORTLAB_ variable read by the source is documented", which will fail on `--record` until T-019 documents it. No other test in that file may fail. State this in the final report rather than editing README.md.

## Notes
- Do not edit `test/agents-topologies.test.mjs`; it imports `runAgents` and checks outcome shapes, and adding `calls` to the outcome must not break it. If it does, that is a regression in your change.
- `--mock` transports return strings, so mock records carry `0` tokens and `null` stop reasons. That is correct: the README pins "a `--mock` run reports `0 in / 0 out`". Do not make the mock invent tokens.
- `role` for a partitioned agent is `leaf`; for shared-lock it is `shared`; `level` is `0` for both. For hierarchical, reuse what `record()` already captures (`valuesIn`, `valuesOut`, `level`, `role`).
- `costUsd` in the summary is computed the way `report()` computes `cost`, from `PRICE[model]`; for a mock run it is `0`.
- Do not touch `src/cost-model.mjs` (T-014 owns it this wave) or `src/pricing.mjs`. `--dry-run` and `--max-spend` are T-016, which runs after this task because both edit `src/agents.mjs`.
- `fs.writeFileSync` the whole record at the end, not a line per call; the harness's own output-path history (`runs/trial-<i>.txt`) is the argument for keeping writes simple.
