# Activity feed: who changed what

Required the first time a customer asks who changed something.

Proves the **audit** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [x] Mutations are recorded with actor, target, action and time
- [x] Recording is not repeated by hand in every mutation
- [x] The feed is queryable per organization and per resource
- [x] Audit rows survive deletion of what they describe

## Watch for

Cross-cutting concern touching every mutation in every feature package. A textbook
case for something the query layer provides once, rather than each package repeating.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.

## Outcome

Recording lives in the query layer, not the action layer — `withAudit()` was built, found
unusable by any call site, and deleted. See `.orchestration/journal/2026-08-27-T-14.md`
and [[L-028]].

The prediction in **Watch for** was right about the shape and wrong about the layer: the
friction was not "each package repeating itself" but "which layer owns the effect". The
answer is the one that owns the resource, because the layer that owns the request grows a
new entry point every other task.
