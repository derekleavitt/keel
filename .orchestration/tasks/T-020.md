# Give project() a fanout parameter

`project()` hardcodes hierarchical fanout at 10. `src/agents.mjs` takes `--fanout`, and
`src/strategies/hierarchical.mjs` reads `SORTLAB_FANOUT`. So the harness can run any tree while
the model can only project one.

Found by T-017 while building `src/compare.mjs`. Comparing a fanout-3 record against the model
gives `tokens in projected 3060 / measured 927`, and that gap is two unrelated things added
together: a real overhead disagreement and a projection of a completely different tree. `compare`
currently prints a warning saying the column is not comparable, which is the honest move
available to it, but a warning that says "ignore this number" is worse than a correct number.

This matters beyond tidiness. The whole point of `compare.mjs` is to attribute error to a named
constant. A projection whose tree shape silently differs from the run's puts an unattributable
term into every hierarchical comparison, which is exactly the confusion the per-call records were
added to remove.

## Acceptance
- [ ] `project({..., fanout})` accepts a fanout and defaults to **10**, so every currently
      documented number is unchanged. Verify byte-identity of `node src/cost-model.mjs` and
      `node src/cost-model.mjs --agents 100` against output captured before the change.
- [ ] `roundCalls` for hierarchical is derived from the given fanout. A fanout of 3 at N=12 gives
      12 leaf, 4, 2, 1 — matching what `agents.mjs --fanout 3` actually produced in T-015.
- [ ] Invalid fanout (0, 1, negative, non-numeric, non-integer) exits 2 naming the flag. Note that
      fanout 1 never reduces and must be rejected, not merely warned about.
- [ ] `--fanout N` on the CLI, shown in the header only when it is not the default.
- [ ] `crossover()` passes fanout through.
- [ ] A test asserts the projected `inputTokens` for N=12 fanout=3 is within a stated tolerance of
      the hierarchical fixture's measured 927, OR documents precisely why a gap remains and what
      constant it is attributable to. Do not tune a constant to close the gap.
- [ ] `npm test` exits 0 with no new failures.
