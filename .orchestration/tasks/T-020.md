# Give project() a fanout parameter, and let compare.mjs project the tree that ran

`project()` hardcodes hierarchical fanout at 10 (`hierarchical: (n, fanout = 10)` is never
called with a second argument). `src/agents.mjs` takes `--fanout`, and
`src/strategies/hierarchical.mjs` reads `SORTLAB_FANOUT`. So the harness can run any tree while
the model can only project one.

Found by T-017 while building `src/compare.mjs`. Comparing the fanout-3 fixture against the
model gives `tokens in projected 3060 / measured 927`, and that gap is two unrelated things added
together: a constant disagreement and a projection of a different tree (15 calls, not 19).
`compare.mjs` currently prints a warning saying the column is not comparable, which is the honest
move available to it, but a warning that says "ignore this number" is worse than a correct number.

This matters because the cheapest real hierarchical run — the one the README already shows
with `--mock` — is 12 agents at fanout 3, about $0.0014. As things stand, that run's record
cannot be set against the model at all. The whole point of `compare.mjs` is to attribute error
to a named constant, and a projection whose tree shape silently differs puts an unattributable
term into every hierarchical comparison.

Regroomed (third grooming): this task now also owns the `compare.mjs` follow-up, because the
intermediate state — `project()` honouring fanout while `compare.mjs` still prints "project() has
no fanout parameter" — is a false statement in the tool's own output, and there is no reason to
commit it. It also picks up one cosmetic defect in the same file (see Acceptance).
