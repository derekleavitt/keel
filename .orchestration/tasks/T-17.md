# Recurring todos

Reminders, digests, cleanup and billing runs all need scheduled work.

Proves the **scheduling** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [ ] A recurrence rule persists and generates future instances
- [ ] Generation is idempotent — running twice does not duplicate
- [ ] Timezone-correct, tested across DST boundaries
- [ ] Editing a series versus a single instance is unambiguous

## Watch for

Idempotency is the hard part and Keel says nothing about it. Expect a lesson.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.
