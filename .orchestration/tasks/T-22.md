# Rate limit the public API

The first abusive client arrives sooner than expected.

Proves the **rate limiting** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [ ] Per-key and per-IP limits with correct headers
- [ ] Shared across instances, not per-process
- [ ] Limits differ by plan
- [ ] A test proves the limit actually blocks

## Watch for

First piece of genuinely shared runtime state. Nothing in Keel addresses it.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.
