# Rate limit the public API

The first abusive client arrives sooner than expected.

Proves the **rate limiting** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [x] Per-key and per-IP limits with correct headers
- [x] Shared across instances, not per-process
- [x] Limits differ by plan
- [x] A test proves the limit actually blocks

## Watch for

First piece of genuinely shared runtime state. Nothing in Keel addresses it.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.

## Outcome

Shared state was the whole difficulty, exactly as predicted: it rules out an in-memory counter,
which is the limit divided by a number nobody chose. Postgres, one atomic statement, sliding
window. See `.orchestration/journal/2026-08-28-T-22.md` and [[L-045]].

The address limit started too tight and the browser suite tripped it against itself — the same
arithmetic an office behind one NAT does.
