# Guard append compaction and pin its atomicity claims

`append.mjs` claims `compact()` is "idempotent, so running it twice is harmless — which matters because 'did the last worker finish' is exactly the question a coordinator gets wrong." But `compact()` is itself a naive read-sort-write: an append landing between its read and its write is lost, which is the exact bug the repository exists to study, reintroduced in the coordinator. The header also asserts `O_APPEND` writes below "the pipe buffer" are atomic and that larger payloads are not; neither is tested. None of the strategy files has a single test.

## Acceptance
- [ ] `test/append.test.mjs` runs 50 concurrent `contribute()` calls (in-process is fine here; the kernel guarantee is what is under test) followed by one `compact()` and asserts the oracle passes, and asserts `compact()` twice yields byte-identical content
- [ ] A test demonstrates the precondition: `compact()` started while appends are still in flight can lose a value (assert that over 20 trials at least one run fails on completeness, or that the new detection below fires)
- [ ] `compact()` writes the sorted result to `<file>.tmp` and `renameSync`s it into place, so a concurrent reader never observes a half-written file
- [ ] `compact()` compares `fs.statSync(file).size` before its read and immediately before its rename; if the size changed it throws an `Error` whose message contains `compacted during writes` instead of overwriting (best-effort detection, documented as such)
- [ ] `contribute()`'s header comment no longer says the guarantee is about "the pipe buffer"; it says `O_APPEND` seek+write is atomic for regular files and cites `PIPE_BUF` only as the conservative size bound used here
- [ ] `node src/run.mjs --agents 12 --strategy append --trials 6` still exits 0
- [ ] `node --test test/append.test.mjs` exits 0

## Notes
- Do not edit `src/run.mjs` (owned by T-007); `run.mjs` already awaits all workers before calling `compact`, so the throw should never fire from the harness.
- `renameSync` over the data file is fine because workers open with `appendFileSync` per call; a worker that appended to the old inode after the rename is exactly the "compacted during writes" case and is a coordinator error.
- Keep `compact(file)` signature; `run.mjs` calls `module.compact(file)` by duck-typing.
