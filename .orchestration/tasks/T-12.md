# Email reminders for todos due today

Anything slow must leave the request path, and password resets alone make transactional email mandatory.

Proves the **async + email** row in `docs/platform-readiness.md`. A capability is not done until
the testbed genuinely uses it, a worked example exists for it, the gate covers it, and the
vendor behind it could be swapped without touching feature code.

## Acceptance

- [ ] A queue exists with retries, backoff and a dead-letter path
- [ ] A daily job finds due todos and sends one digest per user
- [ ] Email has a local development story that does not send real mail
- [ ] A failing job surfaces somewhere a human would actually look
- [ ] Jobs are testable without a live queue

## Watch for

Keel has no async story at all. The reference slice shows a synchronous query layer
only — the design called for a second async slice that was never built. Expect this to
demand it.

A hypothesis, not a specification. If the friction lands elsewhere, that is the more
interesting result — record it.
