# Model per-token latency and find the crossover

The README's thesis is "distribution is a latency tool", but `LATENCY = { api: 1.5, 'claude-code': 8 }` is a constant per round, so `solo` (1 round) is projected at 1.5s for N=100 and still 1.5s for N=1,000,000. Under this model distribution can never win on time either, and the README Open item "Where's the crossover?" is unanswerable with the current code. The model needs output-token generation time and a per-agent work parameter so a sweep can find the N / work-per-agent at which a distributed topology's wall-clock drops below solo's.
