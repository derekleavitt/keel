# Stop the test suite leaving trial files in runs/

`runs/` holds 260 files and grows by 10 every time `node --test test/run.test.mjs` runs
(measured: 250 before, 260 after, exit 0). The source is by design: `src/run.mjs` keeps the
trial file of a failing trial for inspection, and `test/run.test.mjs` deliberately runs trials
that fail — `naive` losing updates, a crashed worker, a thrown trial. The harness behaves
correctly; the test is pointing it at the project's own `runs/` directory. `test/readme.test.mjs`
already solved this for its own runs by copying `src/` to a scratch directory and running the
harness from there, so its trials land under `<scratch>/runs`.

Do the same in `test/run.test.mjs`. Nothing in `src/` changes, so no flag and no `SORTLAB_`
variable is added and `test/readme.test.mjs`'s documentation check is unaffected.

## Acceptance
- [ ] `node --test test/run.test.mjs` exits 0 and `ls runs | wc -l` is the same before and after it, with no other test running (run it twice in a row to be sure the first run was not just cleaning up)
- [ ] The test copies `src/` to a `fs.mkdtempSync` directory at import time and spawns `<scratch>/src/run.mjs`, removing the scratch directory in `test.after`
- [ ] Every assertion the file makes today still holds (naive fails, lockfile passes, crashed worker reported, thrown trial has real elapsed time, worker and runner argument validation)
- [ ] `grep -c "mkdtempSync" test/run.test.mjs` is at least 1 and `grep -c "cpSync" test/run.test.mjs` is at least 1
- [ ] `npm test` exits 0 and `npm run check` exits 0

## Notes
- **Do not delete the existing files in `runs/`.** Other agents are running tests in this tree at the same time, and their in-flight `trial-<pid>-<i>.txt` files live there. Deleting them is the lost-update failure this project exists to document. The owner can `rm -rf runs/` between waves; say so in your report.
- `test/lockfile.test.mjs` and `test/run-isolation.test.mjs` also spawn the harness, but their trials pass and are cleaned up; they were measured to leave nothing. Leave them alone — they are not yours to edit.
- `test/readme.test.mjs` is the pattern to copy (the `fs.cpSync(src(), path.join(scratch, 'src'), { recursive: true })` block near the top). The copied `run.mjs` resolves `root` relative to itself, which is what makes it work.
- A stale `.lock` file was also observed in `runs/` (`trial-53701-8.txt.lock`) from a passing run's cleanup. If you can reproduce it, report the mechanism; do not fix it here — `src/run.mjs` is not in your ownership list.
