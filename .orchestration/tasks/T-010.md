# Add a hierarchical process strategy

The cost model declares and prices a `hierarchical` topology and its comment calls it "the interesting middle", but no process strategy implements it, so the coordination side of the testbed has nothing to say about it. The existing strategies also do not map cleanly onto the cost model's names (`lockfile` ≈ `shared-lock`, `append` ≈ `partitioned`, nothing ≈ `hierarchical`). A process strategy that fans in through group files makes the topology measurable with real OS concurrency and gives T-012 a fourth row for the results table.

## Acceptance
- [ ] `src/strategies/hierarchical.mjs` exports `name`, `contribute({ file, value, delay })` and `compact(file)` with the same shapes as `append.mjs`
- [ ] `contribute` appends `,<value>` to `<file>.g<group>` where `group = Math.ceil(value / FANOUT)` and `FANOUT` reads `SORTLAB_FANOUT` (default 10); it never reads any file
- [ ] `compact` sorts each group file, writes each group's sorted result back to that group file, then k-way merges the group files into `<file>` and deletes the group files
- [ ] `node src/run.mjs --agents 12 --strategy hierarchical --trials 6` exits 0
- [ ] `node src/run.mjs --agents 100 --strategy hierarchical --trials 3` exits 0 and leaves no `runs/trial-*.txt.g*` files behind
- [ ] `test/hierarchical.test.mjs` asserts group-file placement for a few values and that `compact` on 100 appended values passes the oracle; `node --test test/hierarchical.test.mjs` exits 0

## Notes
- Do not edit `src/run.mjs`, `src/worker.mjs` or `src/strategies/append.mjs`. The runner's `compact` hook already handles this strategy by duck-typing.
- Reuse the leading-comma trick from `append.mjs`; the group compaction strips it.
- Compacting per group before the final merge is what makes this "hierarchical" rather than "append with extra files": the merge reads sorted inputs, mirroring the cost model where group mergers emit sorted lists to a root.
- The same `compact`-during-writes caveat as T-009 applies; a size check before rename is welcome but optional here.
