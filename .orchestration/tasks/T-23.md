# A notes editor for a todo

`todo.notes` is in the schema, settable through the public API, searchable, and shown as the
snippet in search results. There is no way to set it in the app.

Found while writing a browser test for T-19 that tried to type into a field which does not
exist. The data model, the API and the search index all support notes; only the interface
does not.

## Acceptance

- [x] Notes are editable from the todo row, saved without a separate form submit
- [x] Editing notes changes what the todo matches in search
- [x] A viewer on a shared list cannot edit them

## Watch for

Small, and the point is the gap itself: a field can be complete everywhere except the one
place a user would meet it, and every layer's tests still pass.

## Outcome

Notes commit on **blur**, not on change: a date picker fires once when a date is chosen, a
textarea fires per keystroke, and saving there is a request per character plus a revalidation
per character racing each other.

Two details the gap exposed. A focus-and-leave with no edit writes nothing — otherwise
tabbing past a todo bumps `updated_at` and wakes every live subscriber to the list. And the
draft adopts the server's value whenever the field is unfocused, so a live update from
another tab (T-20) cannot be silently overwritten by a stale draft on the next blur.

Also passed `canEdit` through to the detail controls, which had been editable-looking for
viewers since T-10 — the server always refused, but the UI never said so.
