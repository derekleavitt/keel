# Close the surviving test race in test/hierarchical.test.mjs

The README's "What this cannot measure" section ends with: one test race survives.
`test/hierarchical.test.mjs` ("real processes via the runner leave no group files") spawns
`src/run.mjs` from the real tree and then asserts that **all of** `runs/` holds no `*.txt.gN`
file. `test/run-isolation.test.mjs` runs in another process at the same time and writes there:
its hierarchical trials create group files transiently, and one test plants three
`trial-99999999-{0,1,2}.txt.g1` files deliberately for the duration of a run. Any overlap fails
the hierarchical test for a reason that has nothing to do with the hierarchical strategy. Wave
four measured it at roughly 1 failure in 30 full-suite runs.

The fix is the one the project already uses twice (`test/readme.test.mjs`, and `test/run.test.mjs`
after T-018): copy `src/` to a `mkdtempSync` scratch directory at import time, spawn
`<scratch>/src/run.mjs`, and assert on `<scratch>/runs`. The copied runner resolves `root`
relative to itself, so its trials land in the scratch tree and the assertion is about this test's
own run and nothing else's. `test/run-isolation.test.mjs` cannot move instead: it asserts
`path.dirname(f) === runs` on the real directory, and that assertion is the point of that test.
