# Drag to reorder, persisted

Reordering must survive a reload, so position is stored, not derived.

## Acceptance

- [ ] Fractional positions; a single drag writes one row
- [ ] Exhausted precision triggers a renumber, inside a transaction
- [ ] A test proves the renumber path actually runs rather than assuming it
- [ ] Order survives reload

## Watch for

Transactions have never been exercised. PGlite can execute them but the concurrency
failure mode it cannot catch is worth naming in a lesson.

This section is a hypothesis, not a specification. If the friction lands somewhere else,
that is the more interesting result — record it.
