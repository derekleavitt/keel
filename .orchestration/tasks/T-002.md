# Test and harden the verify oracle

`src/verify.mjs` is the oracle every result in the README rests on and it has zero tests. Its CLI entry check is `import.meta.url === \`file://${process.argv[1]}\``: `import.meta.url` percent-encodes the path while `argv[1]` does not, so from any checkout whose path contains a space (or other URL-special character) `node src/verify.mjs file N` prints nothing and exits 0 — a silent false PASS. A missing file is also reported identically to an empty one (`missing N: [...]`) rather than as its own failure.

## Acceptance
- [ ] `test/verify.test.mjs` exists and `node --test test/verify.test.mjs` exits 0
- [ ] The test file contains at least one test per oracle property, named so that `grep -c "sorted\|complete\|duplicate\|invented\|unexpected" test/verify.test.mjs` is >= 4
- [ ] Tests pin current behaviour for: multi-line input (fails with `expected 1 line`), trailing comma (fails with `malformed fields`), negative number (fails with `unexpected`), `2.0` (fails with `malformed fields`), empty file with empty `expected` (passes), and a correct `1,2,3` (passes)
- [ ] `src/verify.mjs` main-module detection uses `fileURLToPath(import.meta.url)` compared against `path.resolve(process.argv[1])` (or `realpathSync` of both), and a test spawns `node src/verify.mjs <tmpfile> 3` from a temp directory whose path contains a space and asserts stdout contains `PASS` or `FAIL`
- [ ] A nonexistent path yields a failure string starting with `file not found` in addition to or instead of `missing`, and a test asserts it
- [ ] The exported signature `verify(path, expected) -> { ok, failures, found, expected }` is unchanged (`src/run.mjs` and `src/agents.mjs` import it and are owned by other tasks)
- [ ] `npm test` exits 0 (if T-001 has landed) or `node --test test/` exits 0

## Notes
- Do not change what counts as well-formed (`/^-?\d+$/` with `.trim()`); pin it. Whitespace-padded fields (`1, 2, 3`) and leading zeros (`02`) are currently accepted — write tests that record that fact so a later decision to tighten is deliberate.
- Only `lines[0]` is parsed when there are multiple lines, so a two-line file reports both `expected 1 line` and `missing`. Pin this too.
- The `?? 0` fallbacks in the sort loop are dead code; removing them is fine, changing semantics is not.
- `src/cost-model.mjs` has the same `import.meta.url` bug; that is fixed in T-003, not here.
